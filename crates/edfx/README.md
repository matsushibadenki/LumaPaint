# EDFX 0.1 暫定仕様と Rust プロトタイプ

EDFX（Editable Document Fidelity eXchange）は、編集可能な本文と、保存時に確定した版面を同じファイルに格納します。この試作は固定１ページの横書きを対象とし、段落ごとに英語（`en`）、日本語（`ja`）、简体中文（`zh-Hans`）を指定できます。

**English** · This prototype stores editable paragraphs and the fixed layout of one page. It supports horizontal English, Japanese, and Simplified Chinese. Open a saved file with `inspect` to read the exact line ranges and glyph positions. Use `edit` to replace a paragraph and regenerate the page.

**简体中文** · 此原型将可编辑的段落与单页的固定版面保存在同一文件中，支持英语、日语和简体中文横排。用 `inspect` 读取保存的行范围和字形坐标，用 `edit` 替换段落并重新生成版面。

## ファイル形式

`.edfx` は UTF-8 の JSON オブジェクトです。必須フィールドは次のとおりです。

| フィールド | 内容 |
|---|---|
| `format` | バージョン識別子 `EDFX/0.1` |
| `paragraphs` | 読み順に並ぶ `{locale, text}` の配列。段落内の改行は不可。空文字列は空行１行になる |
| `font` | `{face_index, data}`。OpenType ファイル全体を標準 Base64（パディングあり）で保持し、コレクションのフェイスはゼロ始まりの番号で指定する。可変フォントは既定インスタンスを使う |
| `snapshot` | `{width, height, font_size, lines}`。ページ寸法と、確定した行の配列 |
| `sha256` | 版面・本文・フォントを一組として照合するダイジェスト。64桁の小文字16進数 |

座標は整数で、１単位は 1/1000 pt です。原点はページ左上で、右と下を正とします。

| 項目 | 固定値 |
|---|---:|
| ページ寸法 | 300 × 420 pt |
| 余白 | 四辺 30 pt |
| 文字サイズ | 12 pt |
| 最初のベースライン | 上端から 42 pt |
| 行送り | 18 pt |

各行は `{paragraph, start, end, baseline, glyphs}` です。`paragraph` はゼロ始まりの段落番号、`start` と `end` は元の段落内の UTF-8 バイト範囲（終端を含まない）です。行範囲は段落を先頭から隙間なく覆います。行末の空白も範囲と文字送りに含みます。各グリフは `{id, cluster, x, y}` で、`id` は埋め込みフェイスのグリフ ID、`cluster` は対応する文字クラスタの段落内 UTF-8 バイト位置、`x` と `y` はシェーピング時のオフセットを含むグリフ原点です。合字などによりグリフと文字の対応は多対多になり得ます。

ダイジェストの入力は `[format, paragraphs, font, snapshot]` を余分な空白や末尾改行なしで JSON 化した UTF-8 バイト列です。オブジェクトのキー順は上記の各フィールド定義に記載した順とし、JSON エスケープは Rust の `serde_json` の既定出力に従います。ファイルに含まれる空白やキー順は読み込み時に正規化されます。ダイジェストは破損検出に使います。作成者の認証には署名が別途必要です。

## 組版と保存

Rustybuzz で横書き左から右の字形を決めます。行分割には `unicode-linebreak` の候補を利用し、左から順に候補位置までの行をシェーピングして、行の送り幅が 240 pt を超える直前で折り返します。文字送りとグリフの相対位置をフォント単位で積算し、座標を最も近い整数の 1/1000 pt に丸めます。同距離の場合はゼロから遠い方に丸めます。

１フォントで全文字をカバーする必要があります。埋め込みには、フォント内の OS/2 テーブルが編集可能またはインストール可能と示しているフェイスを指定します。利用条件は使用するフォントのライセンスも確認してください。入力は 1～20 段落、本文の合計 8 KiB、フォント 64 MiB、EDFX ファイル 96 MiB までです。収まる改行位置がない場合や、次のベースラインが本文領域の下端を越える場合はエラーになります。行の収まりは文字送りとベースラインで判定します。組版後は、SVG書き出しと同じアウトライン判定で各字形がページ境界内に収まることを確認します。組版・編集・SVG書き出しでは単色アウトライン字形を扱います。

読み込み時はバージョン、ページ寸法、行範囲、グリフ参照、ダイジェストを検証し、版面を再計算せずに返します。編集時はページ全体を再組版し、字形の境界検査まで成功した時点で本文と版面を同時に更新します。字形がページ外に出ると、グリフID・段落番号・本文内バイト位置を報告し、編集中の本文と版面を保持します。保存時は同じディレクトリ内の一時ファイルに書き込み、同期後に置き換えます。

## 実行と検証

３言語をカバーし、編集埋め込みが許可された OpenType フォントを指定してください。動作確認には Noto Sans CJK JP の可変 OTF を使用しました。

```sh
export EDFX_TEST_FONT="/Library/Fonts/NotoSansCJKjp-VF.otf"
cargo test -p edfx -- --include-ignored
cargo run -p edfx -- new fixtures/paragraphs.json "$EDFX_TEST_FONT" example.edfx
cargo run -p edfx -- inspect example.edfx
cargo run -p edfx -- export-svg example.edfx example.svg
printf '%s\n' '短い文章です。' > replacement.txt
cargo run -p edfx -- edit example.edfx 1 replacement.txt edited.edfx
cargo run -p edfx -- inspect edited.edfx
```

統合テストは各言語で複数行が生成されることを確認します。保存・再読込では行範囲と全グリフ座標を含む版面全体を比較します。日本語段落の短縮後は、その段落が１行になり、後続の中国語段落のグリフが上に移動し、再保存後も一致することを確認します。ページに収まらない編集と改変されたファイルの拒否も検証します。字形の検査では、同じ送り幅を持つ２字形を収録したテスト専用フォントを使用します。左にはみ出す字形への編集が拒否され、本文・版面・再保存したバイト列が一致することを確認します。

## SVG書き出し

`export-svg` は保存済み版面のグリフIDと座標を使い、埋め込みフォントからアウトラインを取り出します。各字形をSVGパスとして保存するため、閲覧側でのフォントの読み込みや組版は不要です。ページの物理寸法と、左上原点の座標を保持します。空白など輪郭のない字形は描画を省略し、カラー字形と画像字形はエラーになります。

字形のベジェ曲線を含む外接矩形をページ境界と照合します。境界に接するだけなら書き出せます。輪郭が境界を越えた場合は、グリフID・段落番号・本文内バイト位置を報告し、出力先への反映を中止します。既存のSVGはエラー時も保持されます。
