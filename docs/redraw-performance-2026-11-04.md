# ピクセル・ベクターの再描画準備の削減

🟢 [Done] 画像・通常パス・線形／円形グラデーションを含むSVGの解析結果をRust側で保持する。文書の表示、表示範囲の描画、オブジェクト表示、画像の境界計算が同じ解析結果を再利用する。ソース全文の一致を確認するため、同じ長さの編集やUndoで古い内容を表示しない。

以前の文字用32 MiB・表示範囲用32 MiBのキャッシュを、合計64 MiBの単一LRUに統合した。最大32エントリー。元データ・ノード・パス・グラデーションの停止点・画像の圧縮データを余裕付きで計上する。これは保持量の見積もりであり、プロセスのRSS上限ではない。描画中のArc参照は退避後も生存できる。複雑なフィルター、パターン、SVG画像の入れ子、予算超過は保持しない。画像のRGBAデコードやラスタライズ自体は従来の処理を使う。

🟢 [Done] ブラシの入力点・筆圧・設定が完全一致し、文書も変わっていない再描画では、点列の再サンプリング、タイル分類、仮合成、アップロード準備を省略する。強制再描画では計算済みの点列だけを再利用し、必要なタイルは更新する。入力が増えた場合・確定・Undo／Redo・文書切り替えは従来の更新経路を通る。追加の保持量はキャッシュ当たり8 MiB以内、選択範囲付きの入力はこの保持対象外とした。

🟢 [Done] 画像移動確定時の16バイトのGPU更新を既存の計測マクロに統一し、GPU書き込みの監査テストも通るようにした。

## 測定

Apple M4、macOS、Rust testプロファイル（core/rendererは既存設定のopt-level 2）、Skia機能有効。同じバイナリで従来の解析＋描画と、保持した解析結果による描画を交互に実行。最初の1回を除いた9回の中央値。800×554の描画先、倍率200%、毎回表示位置を変更した。これはCPU側の表示画像生成時間で、Tauriの入力から物理画面表示までの遅延やFPSではない。

| 対象・処理 | 再解析あり | 解析結果の再利用 |
| --- | ---: | ---: |
| 指定画像と同じPNG：解析 | 118.383 ms | 0.096 ms |
| 同PNG：解析＋表示画像の生成 | 179.754 ms | 59.437 ms |
| 半透明グラデーション楕円600個：解析 | 8.412 ms | 約0.001 ms |
| 同ベクター：解析＋表示画像の生成 | 1253.873 ms | 1245.806 ms |

画像の表示画像生成は約67%短縮。多数の図形が重なるベクター例では、解析の削減よりもラスタライズの負荷が大きい。ベクター全体の大幅な高速化を示す結果ではない。

元のDesktop上のPNGは今回の確認時点で存在しなかったため、前回保存した確認用文書から画像データを取り出した。1672×941、3,094,058バイト。SHA-256は前回の画像と一致する：`f768ef967b2ecf704f8bfebb3d8d683079690686cfcb64306e57757e2d71054b`。画像データはリポジトリへ追加していない。

入力点300個の変化していないブラシについても、保持を外した同一コード経路と保持有効時を比較。結果は[ブラシ計測ログ](performance-redraw-2026-11-04/brush-benchmark.log)に記録した。連続して点が増える描画の速度を測る試験ではない。

## 検証

- 半透明・回転画像、線形／円形グラデーションについて、通常解析と保持解析の描画結果が全画素完全一致。倍率1・2・0.75、整数／小数の表示位置で比較。同じ長さのソース編集、元のソースへの復帰、保持予算も検証。
- ブラシの同一入力で再処理・アップロードなし。筆圧付き入力の追加、強制更新、確定、Undo／Redoを、新しいキャッシュによる全体描画と比較。
- 描画クレート全体：333 passed、0 failed、81 ignored。ignoredは既存の実GPU試験・手動性能試験など。今回の手動性能試験2件は別途実行。
- 警告禁止Clippy（renderer全ターゲット、Skia有効）、Rust整形、依存境界、差分検査、UI／Tauriアプリのビルド成功。
- macOS Tauriで、同PNGの200%表示・往復パン・画像移動・Undo／Redoを確認。ベクター文書の円形／楕円形グラデーションも200%表示・往復パン・レイヤー不透明度100→49→100%の表示更新を確認。確認用文書の変更は破棄した。
- ベクターのキャンバス選択・位置変更は今回の操作では成立しなかったため、位置編集の実機確認完了とは扱わない。ソース変更時のキャッシュ無効化と履歴の正しさは自動テストで検証した。
