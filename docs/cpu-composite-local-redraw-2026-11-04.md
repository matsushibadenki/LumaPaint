# 複合効果のCPU表示修正と小領域の再描画（2026-11-04）

## 実装

- resvg 0.49.0をローカル依存に追加。入れ子のオフスクリーン描画で、子の描画座標と最大描画範囲を同じ原点へ移す。マスクにも同じ範囲を渡す。従来のメモリ上限の寸法は広げず、整数オーバーフローも検査する。
- 通常ベクターのGPU合成テクスチャを保持し、変更オブジェクトの旧／新境界を合わせた範囲だけ透明に消去して再描画。その範囲に重なる上下のオブジェクトも、元の順序で描く。色・クリップ画像・変形・形状の変更を検知する。
- 初回、表示範囲の変更、オブジェクト順序／数の変更、大きな更新、準備失敗後は全体を描き直す。レイヤーの不透明度だけなら保持画像を再利用する。
- CPU部分更新は256pxタイル全体ではなく、各タイル内の実際の変更範囲へ絞る。アンチエイリアスの余白と重なりの再合成を保持する。
- UI追加なし。英語・日本語・简体中文の既存操作を維持し、文書・レンダラーはRust、画像はRust／GPU内に保持する。

## AdobeStockデータの比較

元データは前回と同じ`AdobeStock_1832685201.ai`。EPS形式のため、前回Illustratorで変換したSVGコピーを使用した。SHA-256はAIが`727582ba2a6b1cbc47c752c82ec244b38a10d76291718578ea1dec5121f2f886`、SVGが`a2601b171a41e1bb2c69c57df0029487721de846bff0309a979215bf2fec4ab0`。2,669パス・69グラデーション・870グループ。

前回の複合効果fixture（元図版をアルファマスク、ぼかし／影の合成、グループ不透明度で包んだもの）を再利用した。これらの追加効果が元のAIに存在するという意味ではない。ライセンス付きのAI／SVG／画素画像はリポジトリに追加していない。

全体CPU描画から切り出した参照画像と、表示範囲だけをCPU描画した画像を比較した。下表は乗算済みRGBA、各値は0〜255。大差画素は、いずれかのチャンネル差が32を超える画素。

| 表示 | 修正前の平均差 | 修正後の平均差 | 大差画素（前→後） |
| --- | ---: | ---: | ---: |
| 全体表示 | 0.000126 | 0.000126 | 0→0 |
| 200% | 8.190838 | 0.000174 | 85,175→0 |
| 400% | 8.970655 | 0.000199 | 96,630→0 |

修正後の最大チャンネル差は全体表示7、200%／400%で6。小数座標を含む別の9条件（0.7／2／4倍×3パン位置）でも平均差は最大0.001636、最大チャンネル差6だった。浮動小数点位相による輪郭差は残るため、完全一致とはしていない。合成の模様がまとまって消える欠落は解消した。

合成用の小さな回帰SVGでは、クリップ・アルファマスク・グラデーション・影・透明な重なり・回転を含む9条件すべてで全画素一致。前回のCPU／GPU比較90組も再実行して成功した。この90組の再実行中は別のビルドが重なったため、その実行の時間は性能値として採用していない。

## 小領域の性能比較

Apple M4／Metal、デバッグビルド。同一プロセス内で前後の処理を交互に実行し、初回を除いた中央値。

| 測定対象 | 従来 | 改善後 | 対象範囲 |
| --- | ---: | ---: | --- |
| GPU保持レイヤーの再描画（GPU完了待ち含む） | 7.044 ms | 0.829 ms | 128×128、101オブジェクト、30組 |
| GPU再描画画素／オブジェクト数 | 16,384／101 | 168／3 | 同上 |
| CPUタイル用SVG生成＋ラスタライズ | 0.1247 ms | 0.1114 ms | 半透明オブジェクトの境界変更、20組 |
| CPUラスタライズ画素数 | 135,200 | 12,296 | 同上 |

GPUは約88%短縮、CPUの測定部分は約11%短縮。GPU値は保持済みの小さな合成ターゲットの更新処理で、初回解析・入力・文書通知・画面提示の総時間は含まない。AdobeStock全体の編集や、全操作がこの倍率で高速化するという結果ではない。

8回の形状／傾き／移動変更では、部分GPU更新と強制全体GPU更新が毎回RGBA全画素一致。透明な上下の重なり、レイヤー不透明度を含む。並べ替えとパンでは全体更新へ戻ることも確認した。CPUでもタイル境界をまたぐ変更、透明な重なり、全体画像との一致を確認した。

## Tauri実機確認

隔離したアプリID `app.lumapaint.cpufallbackqa` で起動。`LUMAPAINT_RENDER_METRICS=1 LUMAPAINT_WORKSPACE_FORCE_CPU=1`を指定し、取り込みSVGのGPU経路を診断時だけ無効にした。通常の編集可能ベクターのGPU描画は有効。

- 複合効果付きAdobeStockを200%／400%へ拡大しパン。模様、チェック柄に透ける透明度、影と重なりが保持されることを実画面で確認。ログでもCPUラスタライズ経路の使用を確認。
- 別の101オブジェクトの編集可能データで、ダイレクト選択した1点を移動して変形。レイヤー不透明度100%／60%、透明なオブジェクトの重なり、Undo／Redoを確認。テストデータには実編集用のcontrolPointsを付与した。
- GPUへ戻った確定フレームでは、800×554の443,200画素全体に対して5,544画素だけ更新。通常例は1個、重なり例は2個を再描画し、残り100個の境界を再利用。ホスト側フレームは5.47／5.77ms（2例のみで、安定した応答時間の統計ではない）。
- 選択表示などによってCPUへ戻るフレームもあり、その場合も狭めたタイルの更新を確認。重なり例の確定フレームではアップロード26,840 bytes、描画対象2個だった。全てのドラッグ途中フレームがGPU部分更新になるという主張はしていない。
- 保存した検証用コピーでレイヤー不透明度0.6、`small-33`の節点が`[0,0]`から`[2.25,-2.25]`へ変更されたことを確認。

## 検証と残る範囲

- renderer通常テスト335件成功（任意GPU／実データベンチマーク90件は標準実行ではignore）。別実行のネイティブGPU回帰、CPU複合効果比較、CPUタイル比較も成功。
- Skia有効／無効のrenderer全ターゲット警告禁止Clippy、Tauriビルド、Rust整形、依存境界、ライセンス一覧更新、差分検査を確認。
- vendored resvg単体の`cargo test -p resvg --lib`はworkspace非メンバーのdev-dependency制約で実行不可。アプリ側に追加したCPU回帰テストとrenderer全体テストで検証した。
- Windows／Linux実機は未検証。巨大な単一パスの境界が画面を覆う場合や、未知の複合効果は保守的な全体更新を維持する。CPU／GPUの輪郭差、フィルター境界全般、ドラッグ中のCPUフォールバック削減は継続課題。
