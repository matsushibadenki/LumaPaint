# 節点ドラッグ中のGPU描画（2026-11-04）

## 変更

節点選択のガイドは編集プレビューのSVGレイヤーに線として追加される。塗りとガイドの線が混在すると既存のネイティブパス描画から外れ、旧経路では文書全体のCPU画像を生成し、高倍率では表示範囲のCPU画像も生成していた。

macOS／Metalでは、この編集可能SVGを表示範囲のGPU合成へ直接渡す。通常のネイティブパス描画が使える場合は引き続き優先する。グループ化されていない標準パスについては、オブジェクトごとのSkia描画命令を保持し、変わったパスとガイドだけを再生成する。元の重ね順で描き、レイヤー不透明度は合成後に一度だけ適用する。Rust／GPU側にテクスチャを保持し、WebViewへ画素を転送しない。

命令キャッシュは最大4,096項目・概算16 MiB。既存の全体SVGキャッシュ（64 MiB）とは別枠で、同一フレームの保持量にも上限を設ける。オブジェクトの全状態と文書寸法で照合する。グループ・クリッピング・標準生成SVGとの不一致は、既存の全体SVG描画へ戻す。未対応SVGはCPU描画を維持する。文字・画像・特殊ブレンドは今回の対象外。

ホスト側では、複数の節点ガイドを追加するたびに文書を複製する処理をやめた。拡大縮小・回転・境界ハンドルのプレビューにも、Undo履歴などを含まない描画用文書コピーを使う。編集確定・履歴・保存形式は変更しない。UI追加はなく、英語・日本語・简体中文の既存操作を維持する。

## 再現条件と画像比較

- Apple M4、macOS、Metal、デバッグビルド。960×640文書、表示800×554。
- 編集可能な101オブジェクト。青い100パスの不透明度55%、重なる赤いパス40%、レイヤー60%。
- 節点移動・拡大縮小・回転 × 75／100／200／400% × 9段階 = 108ケース。
- 各プレビューの本文は、独立に編集を適用した文書と一致。元の文書・履歴を変更しないことも検証。
- 保持したオブジェクト命令と全体SVGのGPU描画は、108ケースの全RGBA画素が一致。
- CPU参照との平均RGBA差は最大0.007441/255。32/255を超える差の画素率は最大0.000113（0.0113%）、最大チャンネル差50/255。差は輪郭のアンチエイリアスに残るため、CPUと全画素一致とはしない。
- CPU参照で3×3近傍のRGBAがすべて等しい内部画素は最大差0。半透明の塗り・重なり・背景透明度を維持。
- 別の6条件で、重ね順、色とアルファ、表示／非表示、半透明の円形グラデーション＋線＋傾き、レイヤー不透明度の変更後も全体GPU描画と完全一致。グループと非標準SVGの安全なフォールバックも確認。

今回は編集可能パスの操作を再現する合成文書を使用した。前回のAdobeStockは取り込みSVGで、個々の節点編集の比較資料としては使用していない。

## Tauri実機確認

旧ビルドと最終ビルドを別のQAアプリとして起動し、同じ文書の同じ節点を200%で往復移動した。ガイド、半透明の重なりと移動結果を目視確認。

最初の4往復方向操作（8描画フレーム）では、CPUレイヤーラスタライズ8→0回、SVG画像アップロード107,360→0バイト。改善後は4回の更新でオブジェクト命令6個を生成し、406個を再利用した。`fallback.native_stroke_compositing`は既存の専用パス描画が使えないことを示すカウンターで、これが残っていても新しいSVG GPU経路へ進むため、CPUフォールバックを意味しない。

ただし、最初の改善後操作に431.28ms、53.76msのホスト処理が記録された。この8フレーム全体の中央値は旧5.585ms／新8.395msで、コールド時を含むアプリ全体が高速化したとは結論しない。以降の改善後8ドラッグ・16フレームは中央値4.065ms、CPUラスタライズ・SVG画像アップロード0、更新8回で命令12個生成／812個再利用。自動操作は移動イベントがまとめられるため、連続ペン入力や物理的な表示遅延の測定にはならない。
