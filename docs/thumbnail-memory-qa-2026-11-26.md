# サムネイル更新とピークメモリの再計測

macOSでTauri Release版を別々に起動し、前回と同じ3,600×3,200 pxの4レイヤー文書を使用した。SHA-256は `0ff5bd0ac16bc419a39f3f5b2636b0a9a4240dab3a51ab297b57b4f5bdabea5b`。比較元は前回のサムネイル改善を含むRelease版。両版で表示倍率15.81%、128 pxのブラシを使い、背景マスクに同じ位置で6本描画してUndo／Redoを行った。

| 指標 | 改善前 | 改善後 |
| --- | ---: | ---: |
| サムネイル1要求の平均処理時間（各11件） | 10.49 ms | 9.24 ms |
| ポインターを離してから描画提示までの中央値（各6本） | 181.56 ms | 140.30 ms |
| アプリ本体プロセスのピークRSS | 691.25 MiB | 711.28 MiB |

処理時間は文書スナップショット、サムネイル描画、IPC向けBase64変換の合計。入力遅延はネイティブのpointer-up処理から描画提示までの計測値。RSSはアプリ本体のみ。1組の試行であり、数値には実行時の変動が含まれる。

前回の4試行では初回描画後から最初のブラシ入力前にピークRSSが約132 MiB増加した。今回の両版も最大値は文書を開いた段階で記録され、ブラシ入力やサムネイル更新では更新されなかった。初期表示では原寸SVGのラスタ出力138,240,000バイト（約131.84 MiB）のアップロードが記録された。時期と規模は整合するが、RSSから個々の割り当て元は特定できない。

標準文書のレイヤータブでは、個別チャンネル描画用の文書の複製と描画、チャンネルPNGの生成を省いた。Release版でレイヤーとマスクの表示、マスク描画とUndo／Redoに伴う更新、チャンネルタブの表示を確認した。レンダラーのサムネイルテスト11件が成功し、レイヤーとマスクのPNGが従来の処理とバイト単位で一致することも確認した。タイル方式は既存の処理を使用する。
