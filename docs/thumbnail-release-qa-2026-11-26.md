# サムネイルのTauri Release実機比較

macOS・Apple M4の同一端末で、Tauri Release版を比較した。改善前は `f9bd541` の `thumbnails.rs`、改善後は現行の同ファイルを使用した。両版の依存関係、その他のRustコード、WebView UI、最適化設定、診断設定は共通。

標準文書は前回と同じ3,600×3,200 pxの4レイヤー文書を使用した。SHA-256は `0ff5bd0ac16bc419a39f3f5b2636b0a9a4240dab3a51ab297b57b4f5bdabea5b`。各試行は文書のない新規プロセスで開始し、レイヤーパネルを表示して128 pxのブラシで背景マスクに同じ6本を描き、Undo／Redoを実行した。試行順は改善前、改善後、改善後、改善前。最初の復元タブが残った準備起動は除外した。元ファイルを保存せず、計測後のSHA-256一致を確認した。

| 指標 | 第1組 改善前 → 改善後 | 第2組 改善前 → 改善後 |
| --- | ---: | ---: |
| サムネイル取得回数 | 11 → 11 | 10 → 10 |
| スナップショット・描画・IPC用エンコードの合計 | 300.15 → 160.25 ms | 123.78 → 95.60 ms |
| 同処理の1要求あたり平均 | 27.29 → 14.57 ms | 12.38 → 9.56 ms |
| ペン上げハンドラー開始からpresent呼び出しまでの中央値 | 370.28 → 261.83 ms | 267.12 → 261.04 ms |
| 同区間の最大値 | 392.61 → 267.37 ms | 342.31 → 267.86 ms |
| アプリ本体のピークRSS | 699.63 → 711.08 MiB | 711.42 → 712.31 MiB |

サムネイル時間はRustの公開累積診断値。描画区間はPNG生成を含み、IPC用エンコードはその後のBase64変換。入力遅延は各試行6件のペン上げについて集計し、OSの入力待ちや実ディスプレイの表示時間は含めていない。ピークRSSは親アプリプロセスの `wait4` の値で、WebKit子プロセスと別計上のGPUメモリは含まない。試行間で特に改善前の時間差が大きく、負荷と熱条件を隔離していない。入力遅延の短縮幅は参考値とし、ピークメモリの削減は確認できなかった。

標準文書では、4レイヤーと背景マスクのサムネイル、描画後のマスクサムネイル、QA Blueの非表示に伴う合成サムネイルの更新を目視確認した。タイル文書の機能確認には512×512 pxのシアンとマスク付きコーラルの2レイヤーを使用した。レイヤー、マスク、RGB合成、各色とアルファのサムネイルを確認し、コーラルを非表示にするとキャンバスと合成サムネイルから消え、チャンネルのサムネイルも更新された。性能比較は標準4レイヤー文書で実施した。
