# ラスタータイルと非破壊ドキュメントの移行契約

## 現在の実装範囲

`lumapaint-core::tiles` は256×256の疎なRGBA8タイルを持つ。キャンバス外の矩形、長さが異なる画素入力、古い状態に対するUndo/Redo差分を拒否する。透明画素のRGBは0へ正規化し、全透明タイルは割り当てない。書き込みは変更したタイルの前後だけを返し、差分全体を検査してからUndo/Redoへ適用する。右端・下端のタイルも内部バッファは256×256で、キャンバス外の画素は透明のままにする。

`TiledRasterDocument` は最大16枚の独立したラスターレイヤーを保持し、レイヤーIDを指定した矩形編集を一つの履歴操作にする。Undo/Redoは最後に編集したレイヤーの変更タイルのみを復元し、変更したレイヤーIDとタイル座標を返す。これは将来GPUキャッシュを部分更新するための無効化情報になる。無変更の書き込みは履歴・revisionを増やさず、新しい編集ではRedoを破棄する。

指定座標のタイルは、レイヤー順に通常のアルファ合成を行ったRGBA8の乗算済み画素として取得できる。未割り当て座標は画素バッファを作らず、キャンバス端の余白は透明を保つ。GPU側の部分転送には、編集・Undo/Redoが返す無効化座標だけを再合成する。

`prepare_uploads`は無効化座標を検証・重複排除し、各座標の合成済み乗算RGBA8画素、作品上の転送位置、端で切り抜く幅・高さ、1024バイトの行ピッチを返す。非表示・マスク・Undoで画素が消えた場合もゼロ埋め画素を返し、GPU上の古い内容を消せる。新規GPUテクスチャには`prepare_full_uploads`で初期内容を作る。レンダラーの`TileTexture`は全転送データを検証してからwgpuの該当領域へ書き込み、macOS Metal上で端タイルと透明化を読戻して確認した。現在のキャンバス描画パスはこのテクスチャをまだ合成していない。

タイル文書内では各レイヤーの表示と不透明度、後ろから前への重ね順を変更できる。表示・不透明度の変更はそのレイヤーの割り当て済みタイル、重ね順変更は移動範囲内の全レイヤーのタイルを無効化する。画素編集と同じUndo/Redo履歴に積み、各操作の逆操作でも対応する座標を返す。未変更の設定や無効な不透明度・移動先は文書revisionを変えない。

各レイヤーのロックはブラシと画素置換を拒否する。透明ピクセル保護中は画素置換を拒否し、ブラシが既存の不透明画素のRGBだけを変更してアルファを維持する。両設定は画素転送を要しない履歴操作としてUndo/Redoに積み、変更タイルは空で返す。

既存レイヤー設定と同じ有効化・反転・濃度を持つマスクを合成時に適用する。さらに各レイヤーに場所ごとに編集できる疎な8bitマスクを保持する。未編集画素は255（全表示）で、全画素が255のマスクタイルは割り当てない。マスク値に濃度を掛け、反転時はその結果を反転する。元のRGBAタイル画素は変更せず、マスク編集と設定変更をUndo/Redoに積み、影響するタイルのみを無効化する。ブラシ点は通常の描画と同じ曲線・弧長・硬さ・濃度と選択範囲を使い、指定した0〜255のマスク値へ一ストローク単位で合成する。画面のマスクブラシ操作は未接続。

サンプリング済みのブラシ点を`RasterDab`（中心・筆圧反映後の半径・硬さ・光学濃度の重み）として一括でタイルへ描ける。一本のストローク内では濃度を先に足し、既存画素へ一度だけ合成するため、自己交差を別の不透明レイヤーとして重ねない。変更タイルの差分は一つのUndo/Redo操作になる。無効な点が含まれる場合は描画前に全件を拒否し、重み0やキャンバス外だけなら履歴を増やさない。

既存GPUブラシと同じ曲線補間・弧長サンプリングから`RasterDab`を生成するアダプターを設けた。保存済みストロークの選択範囲はタイル画素の中心で判定し、加算・減算・反転をブラシの濃度蓄積前に適用する。選択範囲とブラシ点は描画前に検証し、無効な入力で文書履歴を変更しない。

`project_committed_paint_layer`はv1文書の確定済みペイントストロークをタイルへ再生し、レイヤーの表示・不透明度・ロック・均一マスク設定を写す。非表示レイヤーのストロークも保持し、再生中のタイル履歴は都度破棄する。移行結果は元文書へ書き戻さず、アクティブな入力ストローク、SVG／ベクターレイヤー、保存revisionは対象外とする。

これは共通コア内の独立した文書モデルであり、現在のブラシ描画・画面のレイヤー・保存ファイルはまだストローク／SVGのv1モデルを使う。したがって、タイル操作だけでアプリの表示や保存内容が変わることはない。

## 次の接続

1. 疎なマスクとロック・透明ピクセル保護を既存の画面レイヤー操作へ接続し、マスクブラシの入力をタイル文書へ送る。レイヤーの並べ替えではタイルを複製しない。
2. タイル側の1作品ピクセルのアンチエイリアス幅とRGBA8合成を、現在の表示倍率・線形色のGPU描画と照合してから切り替える。既存文書のUndo/Redo・保存revision・描画世代へ接続し、GPUへは変更タイルだけを送る。
3. v1ファイルは従来どおり読み込む。タイルを永続化する段階で新しい形式バージョンを導入し、マニフェストにドキュメント寸法・レイヤー順・色空間・処理ノード・タイル参照を記録する。各タイルの座標・形式・サイズ・チェックサムを検証してから文書へ採用し、未知のノードや破損した参照は黙って描画しない。
4. 処理グラフは元画像／ベクター／文字、マスク、フィルター、合成を別ノードにする。ノード入力の変更時は影響するタイルのキャッシュだけを無効化する。AI生成の入力・モデル・結果参照も後続のノード種別として扱い、結果画像だけで元の設定を失わないようにする。

現段階のRGBA8は既存のブラシとの接続用であり、最終的な作業色空間やRGBA16F、ICC/CMYKの実装を確定するものではない。形式移行時は色空間と画素形式をタイルごとに明記する。
