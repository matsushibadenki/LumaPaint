# 非破壊ドキュメントと処理グラフの実装契約

この文書は次期プロジェクト形式の実装境界を定める。現在の `.lumapaint` v1、画面のレイヤー、復旧コピーは変更しない。v1 はストロークと SVG を保持する JSON であり、現在のタイルは表示用キャッシュである。以下の形式は未実装で、段階的に導入する。

共通コアにはグラフ型と検証、v1文書からの読み取り専用の構造投影を追加済み。投影はレイヤー順・表示・不透明度・均一マスク設定を表し、元画素やSVG本文は引き続きv1文書が所有する。疎なRGBA8画素、8bit空間マスク、レイヤー順と設定は`TiledRasterState`として履歴なしで書き出し・検証復元できる。これは画面セッション・復旧・次期コンテナが共有する意味上の境界である。独立したバイナリコンテナは形式識別子、版、全体長、JSONマニフェスト、固定長タイル参照、マニフェストと各タイルのCRC32を検査し、隙間や未参照ペイロードを許可しない。プロジェクトファイル層には512 MiBの読み書き上限と既存と同じ原子的置換を使うAPIを追加した。共通読込は形式識別子でv1 JSONとタイルコンテナを分岐し、macOSの「開く」はタイル形式をv1として誤解析しない。文書タブ・復旧処理はまだv1 Document専用で、検証済みタイル文書を画面セッションへ採用して保存・再読込する処理は次工程。
既存タイル文書の`TileInvalidation`は、画素ソースまたはマスクを起点に依存ノードの変更座標へ変換できる。露光・合成・マスクでは座標を引き継ぎ、ぼかしでは`radiusPx`を有限のサンプリング半径として周辺タイルまで保守的に広げる。キャンバス外は除外し、存在しないソースや範囲外の変更座標は拒否する。macOSのブラシ確定ワーカーでは保持中のラスタ文書を構造投影し、Outputに届いた座標からGPU転送データを生成する。表示・不透明度・均一マスク設定の差分更新、およびUndo/Redoで比較する候補タイルもOutputの座標を用いる。空間マスク画素の画面編集、複数ラスターレイヤーの合成、フィルター描画はまだこの経路に接続していない。

## 文書の正本

- 正本は元の画素タイル、SVG／文字オブジェクト、編集可能なマスク、処理ノードのパラメータ、レイヤー順である。合成済み画素と GPU テクスチャは再生成可能なキャッシュとする。
- レイヤー ID とノード ID は文書内で一意で、名前の変更や並べ替えでも変えない。参照は ID で行い、配列位置や表示名を参照先にしない。
- 画素タイルは文書座標の 256×256 とし、端の有効寸法を明記する。未割り当ての画素タイルは透明、未割り当てのマスクタイルは全表示の 255 とする。画素形式と色空間はタイルごとに宣言する。
- 編集操作は正本だけを変更する。フィルター結果の固定化は明示的な「ラスタライズ」操作で新しい元画素を作り、元のノードを勝手に置換しない。

## 処理グラフ

| ノード | 入力 | 出力と役割 |
| --- | --- | --- |
| RasterSource | タイル参照 | 元画素を供給する |
| VectorSource | パス／SVG／文字 | 編集可能な形状と文字を描く |
| Mask | 8bit タイル、反転、濃度 | 元画像を変更せずに入力のアルファを制御する |
| Filter | 入力ノード、型付きパラメータ | 入力から画素を計算する |
| Composite | 順序付き入力、表示、不透明度 | 通常のアルファ合成でレイヤーをまとめる |
| Output | 合成ノード | ドキュメントの表示結果を指定する |

グラフは Output から到達できる有向非巡回グラフとする。ノードの型ごとに入力の個数と型を検証し、循環、欠落参照、重複 ID、非有限パラメータを拒否する。未知の必須ノードを無視して開くと作品が変わるため、対応できない形式は読み込み前に明示的に拒否する。将来の AI 生成ノードも入力、モデル識別子、パラメータ、結果参照を別々に持つ。外部モデルを開くたびに実行しない。

評価キーはノード ID、パラメータ世代、入力の世代、タイル座標、作業色空間、画素形式、表示解像度から作る。正本の変更時は依存する下流ノードだけを無効化する。マスクの矩形編集は該当タイル、半径を持つフィルターは必要な周辺タイル、全画面処理は全タイルを無効化する。影響範囲を宣言できないノードは安全側の全量無効化にする。画面へ渡す無効化情報は文書 ID、revision、タイル座標を含み、古いワーカー結果を採用しない。

Undo/Redo は正本への操作と変更前後の値を記録する。ブラシ一本やマスク一本を一操作とし、タイル差分は変更したタイルだけ保持する。キャッシュや GPU 転送バイト列は履歴へ含めない。保存済み revision と現在 revision の比較は現行の未保存表示を維持する。

## 次期保存コンテナ

新形式は v1 JSON を同じ `version` で拡張しない。現在の試験用コンテナは`LPTILE2`の形式識別子と独立した整数バージョンを置き、最大1 MiBのマニフェストと最大512 MiBの非圧縮タイルデータを持つ。マニフェストには文書寸法、レイヤー順・設定、RGBA8／8bitマスクタイルの座標・位置・長さ・CRC32を記録する。処理グラフ、解像度、色設定、画素形式宣言、圧縮方式は正式な保存接続前に追加する。データ位置は連続かつコンテナ内に限定し、隙間や未参照末尾を拒否する。

読み込みは次の順に進める。

1. コンテナ全体とマニフェストのサイズ・個数上限を検査する。値は実装時に現在の 8192px 文書上限とメモリ予算から確定する。
2. 形式・バージョン・必須フィールド・グラフ参照・色設定を検査する。
3. タイル位置の範囲と重なり、座標、有効寸法、宣言された長さ、圧縮解除後の長さ、チェックサムを全件検査する。宣言値だけを信じて巨大なメモリを確保しない。
4. 検査済みの新文書を構築してからアクティブ文書と交換する。途中の失敗では開いている文書を変更しない。

保存は同じディレクトリの一時ファイルへ書き、同期後に置換する現行の原子的な流れを引き継ぐ。手動保存の外部変更検知、復旧コピーの排他と削除順序も維持する。コンテナ移行時には復旧コピーの形式を別途更新し、古い復旧コピーを先に破棄しない。

## v1 からの移行順序

1. v1 ファイルは従来のデコーダーで読み、ストロークと SVG／文字の編集可能な情報を保持したまま新しい正本へ変換する。開くだけでは元ファイルを書き換えない。
2. 既存のペイントストロークは再描画可能な入力として保持し、タイル化が必要なときに RasterSource を生成する。v1 の表示・不透明度・均一マスクは対応する処理ノードへ移す。現在の v1 には空間マスク画素がないため、存在しないデータを作らない。
3. 画面のブラシ・マスク・レイヤー操作を新しい正本と共通履歴に切り替える。表示結果と保存・再読込を v1 作品で照合してから、新形式での保存を有効にする。
4. v1 への上書き保存を暗黙に行わない。新機能を使った作品は新形式として別名保存し、v1 の読み込みは維持する。

色モードの UI 設定は現時点で CMYK や 16／32bit の演算精度を保証しない。新形式に色設定を記録することと、その色で正しく演算・書き出しできることを別の完了条件にする。macOS を先に実装し、他 OS のホスト接続は ROADMAP の `[Pending]` を維持する。
