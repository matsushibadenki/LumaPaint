# マスク・フィルター・レイヤー効果付きSVGのGPU表示（2026-11-04）

## 実装範囲

macOS／Metalの取り込みSVG表示を拡張。輝度マスク・アルファマスク、Gaussian blur、Offset、Flood、Composite、ColorMatrix、Merge、ComponentTransferをGPUで描画する。透明な色、グループの不透明度、クリップと重なりを維持し、表示用の描画命令を既存の上限付きキャッシュで再利用する。

SkiaのSVGマスクは輝度として処理されるため、アルファマスクの描画内容だけを「RGBを白、アルファを保持する色行列」で包む。変換対象はusvgによる正規化済みデータだけで、ユーザーのSVGソースや保存形式を変更しない。

アプリのレイヤーエフェクトは共有GPUテクスチャを既存のwgpu計算処理へ直接渡す。UNORMビューで前乗算RGBAを読み、既存の色補正・カーブ・マスク・スクリーントーン処理と不透明度の適用順を共有する。CPUへの画素読み戻しや表示画像の再アップロードは不要。エフェクト処理が使えない場合は、未補正画像を表示せず従来経路へ戻る。キャッシュの判定には処理経路の可用性も含める。

GPU化の対象外は、連鎖マスク／クリップ、同一グループの複数フィルター、特殊な合成・isolation、パターン、画像・文字、未検証のフィルタープリミティブ（feDropShadow、Turbulenceなど）。影はGaussianBlur＋Offset＋Flood＋Composite＋Mergeの組み合わせに対応する。これらの対象外や資源上限超過、Windows／Linuxでは従来描画を保持する。小さな表示領域のレイヤー効果には既存のGPU採用下限も適用される。

UI・文書形式の追加はなく、既存の英語・日本語・简体中文UIで共通のRust描画処理を使用する。

## 画質比較について

半透明の前乗算RGBAを比較する。完全一致を主張しない。密な輪郭ではCPU／GPUのアンチエイリアスが異なり、ぼかしの計算方法にも丸め差がある。

従来の表示範囲だけを描くCPU経路には、ぼかしの画面端と、マスク・影・グループ不透明度を重ねた拡大表示に差異が見つかった。後者は模様の一部が欠落する。比較ではこの差を許容値の拡大で隠さず、同じ倍率・画素位置で図版全体をCPU描画してから表示範囲を切り出す参照も使用する。これは試験用の参照生成であり、本番のCPUフォールバック処理の修正ではない。

## 比較結果と限界

90組のRGBA平均絶対誤差は0.200〜0.892/255、アルファの平均誤差は0〜0.751/255。複合2条件は全体CPU参照からの切り出しを基準とした。それ以外は従来の表示範囲CPU描画を基準にし、ぼかしについては32px余白付き参照とも追加比較した。

差が32を超えるチャンネルを持つ画素は最大1.2825%（影・全体表示）。最大チャンネル差は187/255。平均誤差だけで「完全一致」とは扱わない。画面端24pxを除き、参照画像の3×3近傍で16/255を超える変動のない領域に残った差32超の画素は、各条件最大1個だった。密な輪郭のAA差と画面端のフィルター入力範囲の差が主な残差である。

ぼかしの200%／400%では、32px余白を付けてCPU描画してから切り出すと最大差が15／14に下がり、差32超の画素は0個になった。複合200%の旧CPU表示では平均差8.543/255、差32超19.33%という欠落がある一方、全体CPU参照とのGPU比較は上記の小さな差に収まった。

小さな回帰画像では半透明の重なり、黒色アルファマスク（中央RGBAが正確に128,0,0,128）、輝度マスク、色行列、ガンマ／テーブル変換、算術合成、影、表示位置変更を検証。GPUテクスチャ入力によるレイヤー補正は、同じ入力RGBAを既存のバッファ入力処理に渡した場合と全画素完全一致した。反転／密度付きレイヤーマスク、不透明度1・0.43・0も含む。
