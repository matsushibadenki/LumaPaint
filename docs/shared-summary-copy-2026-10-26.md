# 文書要約の再利用と共有通知の中継コピー削減（2026-10-26）

## 実装

共有文書の変更通知では、操作元のworkspace用に要約を生成した後、共有ミラー用に文書から同じ要約をもう一度生成し、さらに共有ビューへの配信ループに入る際にも全体を複製していた。

操作元で生成した要約を、文書IDが一致する場合に共有ミラーへ再利用する。共有ミラーはメインスレッド内の読み取り専用 `Rc<DocumentSnapshot>` とし、配信ループへの中継では参照カウントだけを増やす。更新は新しいRcへの置換なので、以前に取得した通知元の内容は変わらない。文書・履歴・画素を共有要約に所有させない。

同一の変更通知では、従来の「要約生成2回＋中継用の全体複製1回」を「要約生成1回＋ミラー保持用の全体複製1回」にする。各配送先の独立した通知キャッシュへ渡すための所有コピーは引き続き必要であり、今回の削減対象に含めない。

共有ミラーを準備してから操作元へ通知し、その後に共有ビューへ通知する。操作元→共有ビューの配送順序は維持する。revisionだけによる省略は行わず、選択など版が増えない状態もその通知の要約へ反映する。ID不一致・要約なし・アプリハンドルなしでは、必要に応じて従来の標準／タイル文書の要約生成にフォールバックする。文書を退避するときも最新要約を再生成する。共有でない文書はミラー用コピーを作らない。
