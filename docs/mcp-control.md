# AIによるLumaPaintの操作：MCP実装計画

この文書は段階的な実装計画。現在の実装範囲は末尾の「ローカル接続基盤」を参照。AIがLumaPaintを使い、観察・制作・検証・修正・保存まで完結できることを目標とする。macOSを優先し、他のプラットフォームへの接続は `[Pending]` とする。

## 二つの操作系統

同一のRustサービスに、GUI制作とエンジン処理の二つのツール群を設ける。クライアントは片方だけでも両方を組み合わせても利用できる。以下のツール名は設計上の仮称であり、実装済みAPIではない。

| 系統 | 主な用途 | 操作と結果 |
| --- | --- | --- |
| `gui.*` | ユーザーと同じ画面を見ながら制作 | メニュー、ツール、パネル、ダイアログ、キャンバス入力を操作し、UI状態・スクリーンショット・描画完了を取得 |
| `engine.*` | 正確な編集、大量処理、画像処理・生成 | 文書・レイヤー・オブジェクトIDと数値パラメータでRustエンジンを操作し、成果物と処理結果を取得 |

GUI系統も実際のUIイベントと操作ハンドラーを通す。内部データを変更しただけの操作をGUIクリック成功として扱わない。エンジン系統は画面座標やWebViewの存在に依存せず、ヘッドレス処理と開いている作品の編集に対応する。

## 共通基盤と操作契約

- RustがDocument／State／Rendererの正本を所有する。MCP、GUI、ヘッドレス処理は同じ検証・編集コマンド・Undo/Redo・描画基盤を使用する。TauriウインドウやMCP接続ごとに独立した作品状態を複製しない。
- `capabilities`でツール、対応形式、利用可能な処理・生成プロバイダー、上限、バージョンを発見できる。未実装機能は利用可能として返さず、機能追加と同時にMCPへの公開・適合テストを追加する。
- 対象をsession／document／window／layer／objectの安定IDで指定する。単位、座標系、色空間、アルファの扱い、文字範囲のインデックス規約をスキーマで明記する。
- 変更命令に期待revisionとrequest IDを持たせる。ユーザー操作との競合は明示的に返し、再試行で同じ操作を重複適用しない。成功時は変更後revision、変更対象、警告、Undo可能性を返す。
- 複数操作のトランザクション、プレビュー、確定、取消、Undo/Redoを用意する。非原子的な処理は途中結果と失敗箇所を返し、原子的であるかのように扱わない。
- 長時間処理はjob ID、進捗、取消、期限、エラー、結果参照を提供する。文書・UI・ジョブの変更通知とrevisionに基づく待機に対応し、固定時間のsleepに依存しない。
- 状態更新完了とGPU描画完了を区別する。指定revisionの描画完了を待って画像を取得できるようにし、古いスクリーンショットを成功結果として返さない。
- 画像・タイル・テンソル・GPUテクスチャなど大容量データはRust／GPU側に保持する。MCPは命令・設定・ID・メタデータ中心とし、必要な範囲・解像度のプレビューや成果物だけをリソース参照／ファイルとして受け渡す。

## GUI制作MCP

- ウインドウと文書の一覧・切替、フォーカス、ツールモード、アクティブツール、選択対象、ズーム・パン、開いているパネル／メニュー／ダイアログを取得する。
- UI要素に言語や表示文言から独立した安定IDを付ける。要素ツリーから役割、値、選択・有効状態、境界、実行可能アクションを取得し、クリック、値変更、文字入力、メニュー選択を行う。英語・日本語・简体中文で同じ操作IDを使う。
- ポインター移動、押下・解放、クリック、ドラッグ、スクロール、キー・修飾キー、文字入力を提供する。キャンバスの描画は時刻・筆圧・傾き付き点列を受け付け、通常入力と同じ補間・確定処理へ渡す。
- 画面／ウインドウ／キャンバス／文書座標の変換を提供し、Retina倍率、ズーム、パン、複数ディスプレイに対応する。切断・取消時に押しっぱなしのキーや未完了のドラッグを解除する。
- WebViewだけでなくネイティブwgpuキャンバス、ネイティブ文字編集、メニュー・ダイアログを含めた画面確認に対応する。UI付き画面と作品だけのレンダリングを区別し、部分画像も取得できるようにする。
- 成功条件に基づく待機、ヒットテスト、選択境界、文字オーバーセットなどを取得し、AIが制作結果を確認して修正できるようにする。

## 内部エンジンMCP

- 文書の新規作成・テンプレート・読込・保存・複製・書出し、寸法・解像度・色設定・アートボードを操作する。
- レイヤー／グループの作成・削除・順序・表示・ロック・不透明度、オブジェクトの検索・選択・属性・変形を操作する。不適合レイヤーやロックは通常編集と同じエラーを返す。
- ラスターのストローク、消しゴム、塗り、選択範囲、マスク、チャンネル、切り抜き、サイズ変更、合成、色補正、フィルターを公開する。未実装の処理は基盤実装に合わせて段階的に公開する。
- ベクターのパス・ベジェ節点・塗り・線・パス演算、文字・範囲書式・段落・テキストフレーム・配置を構造化命令で操作する。ページやアニメーションも基盤完成後に同じ方式で公開する。
- パラメトリックな図形・パターン・質感の生成と、AIモデルによる画像生成を区別する。画像処理グラフやバッチを実行し、入力・設定・結果を再利用できるようにする。
- AIプロバイダー抽象化に接続し、テキストからの画像生成、参照画像による生成、選択範囲の生成塗りつぶし、拡張、バリエーションを扱う。モデルが対応する機能・サイズ・seed等を発見できるようにする。LumaPaintの描画エンジン自体を生成モデルとは扱わない。
- 生成結果はまず候補として保持し、比較・採用・破棄・レイヤーへの配置を提供する。元画像を保持し、入力参照、プロバイダー／モデル版、設定、seed、日時、結果IDを追跡する。再現性を保証できない処理はその旨を返す。
- ウインドウを開かないバッチ、オフスクリーンwgpuレンダリング、タイル単位処理、メモリ・GPU予算と同時実行制限を提供する。GPUやフォント、生成モデルが利用できない場合は明確なエラー／対応済みの代替処理を返す。

## 接続とユーザーとの共同作業

- 初期はローカルMCP接続を対象とし、stdioアダプターから起動中アプリのRustサービスまたはヘッドレスホストへ接続する。接続方法の詳細は実装時にMCP仕様・採用SDKの互換性を確認して決定する。
- 認可したセッション内でAIが連続して制作できるようにする。対象文書、読み書き可能なファイル範囲、外部プロバイダー送信・課金の権限を接続時に管理し、範囲内の通常編集で毎回確認を求めない。
- アプリにAI接続状態、操作履歴、実行中ジョブ、一時停止・停止を表示する。ユーザー編集とAI操作はRust側で直列化／競合検出し、未保存の変更を黙って上書きしない。
- ファイル操作と外部生成は認可範囲を検証する。任意シェル実行や任意コード評価を制作APIの代わりに公開しない。秘密情報は資格情報ストアに保持し、ツール応答やログに出さない。
- リモート接続は後続段階とし、認証・暗号化・接続権限・レート制限を設計してから公開する。

## 段階と完了条件

1. `[Next]` 共通コマンド境界、能力一覧、安定ID・revision・ジョブ・接続認可を設計し、ローカルMCPの縦断実装を行う。GUIで新規作成→ブラシ描画→画面確認→Undo→保存、エンジンで新規作成→図形・文字配置→レンダリング→書出しが完結することを確認する。
2. `[Later]` 既存の制作機能を両系統に展開する。GUI操作とエンジン操作で同じ文書・描画結果になること、三言語、Retina、複数文書、ユーザーとの競合、切断・再接続、取消・再試行を回帰テストする。
3. `[Later]` ヘッドレス・バッチ・処理グラフ・画像生成プロバイダーを接続する。生成候補の採用、非破壊編集、進捗・取消、成果物の再読込、メモリ／転送量を検証する。
4. `[Later]` リモート接続、追加クライアントとの適合、長時間の自律制作セッションを検証する。
5. `[Pending]` Windows／LinuxのGUIアダプター、接続・配布、GPU／文字組版を実機検証する。

各段階は、ツールが応答するだけでは完了としない。実際の作品状態・保存後の再読込・レンダリング結果を検証し、対応範囲と未対応操作を能力一覧に反映する。


## ローカル接続基盤（実装済み範囲）

`cargo build -p lumapaint-mcp`で`target/debug/lumapaint-mcp`を生成し、MCPクライアントのstdioサーバーコマンドにその絶対パスを指定する。起動引数・ネットワーク接続・資格情報は不要。MCPの2025-11-25初期化ハンドシェイク、ping、tools/list、tools/callに対応する。

- `lumapaint.capabilities`：実装済み機能、上限、実行環境を返す。
- `engine.document.create`：`name`、`width`、`height`で白背景・RGB/sRGB・8bit・72ppiの文書をRustコアに作成する。幅・高さは1〜8192px。
- `engine.document.get`：文書IDとrevisionを含むスナップショットを返す。

現在はプロセスごとに一時文書を1つだけ所有する独立エンジンホスト。起動中のGUI作品とは接続していない。同じ作成引数の再送は同じ結果を返し、別の作成要求で既存文書を上書きしない。ファイル入出力、編集・レンダリング・生成・GUI操作はまだ公開していない。終了時に一時文書は失われる。メッセージは64KiB以下とし、超過時は接続を終了する。

次段階ではこのプロトコル入口を共有Rustサービスへ接続し、文書ID指定・revision検証を伴う編集、履歴、描画・成果物、GUI操作へ拡張する。一般的なMCP SDK／クライアントとの相互運用試験は後続で行う。

参照仕様：[MCP 2025-11-25 tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。
