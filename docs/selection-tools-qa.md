## Selection transform detail preservation — 2026-10-22

Transform now samples the selection footprint, rather than a reduced image of the entire page. Ordered replace/add/subtract/intersect/invert operations and grayscale Quick Mask strokes determine conservative support. A one-pixel border includes soft brush fringes; off-page support is retained. Footprints up to 4,194,304 pixels use document-pixel resolution. Larger footprints use an aspect-preserving reduced grid bounded by that pixel budget; they do not guarantee one-pixel detail. Existing run-count and matrix validation limits still apply, and rejected edits leave the current selection intact.

Scaling, rotation, shear, reflection and fractional translations of raster selections use bilinear coverage with transparent samples outside the mask. CPU and WGSL use texel-center coordinates. Previously saved masks default to nearest sampling, and render-only coordinate scaling preserves the stored interpolation choice. Integer translation of a nearest mask keeps nearest sampling. Repeated affine edits retain source pixels and compose matrices; they do not repeatedly resample or blur the source. Run data is Arc-shared through edits/history, with the same JSON array format and an optional interpolation field. Vector-mask cache keys include this field. Rectangle/polygon transforms remain geometric; ellipses retain the existing 128-segment approximation.

The existing selection command now dispatches Transform through a Rust worker. It evaluates selection geometry without rendering a page image; only parameters and the existing summary cross IPC. Commit checks document ID, revision, selection, layer and an active paint stroke. A successful edit creates one undo entry; rejected stale work cannot finish an in-progress stroke. No new controls or translated labels were introduced.

The macOS mouse workflow was subsequently exercised as described below. Pen/multiwindow operations, Windows/Linux hosts, higher-budget/tiled selection masks, area-filtered downscaling and adaptive ellipse tessellation remain unverified or unfinished. ## Cropped high-resolution refinement and surface retries — 2026-10-23

Inversion is a document-bounded operation over the cropped mask, so it selects outside the crop without downsampling its detail.

Regression cases exercise one-pixel rectangles on an 8192px page, one-step expansion/shift, gray alpha, full-page inverse outside the crop, unchanged geometry, off-page selections, large-footprint budgeting and boolean holes. Cropped results for all five Modify operations and Refine are compared against full-resolution filtering at document edges. A Metal test compares feathered cropped masks and their inverses with CPU clipping. The transform regression also verifies that gray painting cannot drop earlier selected regions.

Static investigation found a lost-request path: `redraw` clears FRAME_REQUESTED before rendering; surface Timeout/Occluded returned Ok without advancing presentation_serial; frameTick then paused its display link. If no later event arrived, the previous frame could remain indefinitely. This is a concrete recovery defect, but does not prove the original intermittent GUI stall had this cause. Renderer now reports missed acquisition separately. The host queues one delayed wake per canvas, backing off from 16ms to 1s; successful rendering, hidden views, hard errors, destroyed/recreated canvases and stale generations cancel or reject callbacks. It does not keep the display link spinning while waiting. A timer never retains a document or pixel payload.

Diagnostics require `LUMAPAINT_RENDER_METRICS=1`. Logs record `surface_acquire_timeout` / `surface_acquire_occluded`, `surface_retry`, and render `presented` / `serial`. Opt-in `LUMAPAINT_DIAGNOSTIC_SURFACE_TIMEOUTS=1..32` skips that many initial acquisitions through the same retry path for deterministic native QA; without metrics, invalid values or values above 32 it has no effect. This simulates acquisition failure, not an actual Metal driver timeout. Persistent natural occlusion and long-session failures still need field reproduction.

### QA launch crash report — 2026-10-23

The supplied crash report records the first, restricted-shell launch of the temporary `app.lumapaint.boundary-qa` bundle at 16:50:35 JST (PID 17772). It aborts in HIServices `_RegisterApplication`, reached from AppKit `NSApplication::sharedApplication` while Tauri/tao constructs the event loop. No document, selection worker or renderer frame appears in the crashing stack. That launch returned exit code 134 before producing application logs. The retained executable's Mach-O UUID (`3AC9B4F2-A54D-3C7A-8778-B63CB2510195`) exactly matches the report.

The same executable was then launched with approved access to the desktop GUI services. That run produced the Metal presentation/retry logs and completed the selection, save, Undo/Redo checks above; quitting returned exit code 0. This evidence points to GUI process registration failing under the restricted launch environment. The report does not provide the underlying registration error, and the narrowly scoped unified-log query returned no entries, so no specific macOS registration error code is claimed. This startup abort is distinct from the earlier canvas stall after editing.

Future native GUI QA should start through a desktop GUI-capable launch path from the outset. Do not first probe launchability by directly starting AppKit from the restricted shell. This follow-up changes the verification procedure and records the incident; it does not introduce an application-code workaround for the OS registration abort. The temporary bundle has already been removed.
