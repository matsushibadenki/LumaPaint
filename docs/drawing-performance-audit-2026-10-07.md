## 今回の測定

環境は開発端末のmacOS 27.0.1 / arm64、Release（thin LTO）。処理ごとに順番に実行。実アプリの画面解像度・操作セッションを固定した測定ではない。端末上の他アプリ負荷、GPU時間、入力から表示までの遅延、ピークRSS/VRAMは測っていない。fps達成や改善後の倍率は保証しない。

### ベクターと共通処理

矩形1,000／4,096個から1個を移動。20回ウォームアップ、1秒×3回。snapshotとcloneは各20回、生成を計測し破棄を計測区間外に置く。cloneの試料は長大な編集履歴を持たないため、長時間作業の上限値ではない。

| 個数 | 移動 p95（3回の範囲、µs） | UI snapshot 中央値（ms） | Document clone 中央値（ms） |
| --- | ---: | ---: | ---: |
| 1,000 | 2.125–2.167 | 0.662 | 0.157 |
| 4,096 | 2.459–2.583 | 1.208 | 0.356 |

移動の履歴変形値80 bytes、SVGパッチ45 bytes、全レイヤー履歴複製0、SVG全生成0、全ID走査0を確認。これは対応する通常移動のコア処理であり、通知・復旧・描画を含まない。UI snapshotはJSON化やWebView転送を含まない。詳細は [CSV](performance-2026-10-07/vector.csv)。

### ピクセル

既存の `a4_preview_transfers_changed_tiles_and_preserves_curve` をReleaseで実行。2480×3508、20pxブラシ、69回の曲線更新。

- CPU処理中央値4.16ms、最大8.50ms（単一試行。p95/p99や60秒試験ではない）。
- 生成された変更タイルのアップロード用画素ペイロードは合計22.75MiB。毎回全画像を用意した場合の計算値は2289.92MiB。
- この試験はGPU queueへ実際に転送しない。上記は実バス転送量ではない。
- 全再構成との画素一致、未変更更新のアップロード用ペイロード0、消しゴムによる透明画素の更新を確認。

変更タイル化はすでに有効。一方、長いストローク全体の再適用は残っているため、点数・ブラシ径・レイヤー効果を増やした測定が必要。

### テキスト

英語・日本語・简体中文を混ぜた5行／45行、2048×2048文書。各条件で1回ウォームアップ後3回平均。ラスタ化ベンチマークはSVG解析・文字処理・画像生成を含む。AppKit入力、IME、メインウインドウ合成、入力遅延は含まない。実際に選ばれたバックエンドもログに記録するようにした。

バックエンド名を記録した再実行では、今回の試料はすべて **Resvg（CPU互換ラスタ化）** を選択した。これは既存の共有Metalテクスチャ経路の速度ではない。

| 試料 | 2048px | 1024px | 512px |
| --- | ---: | ---: | ---: |
| 5行 | 37.3ms | 35.6ms | 34.7ms |
| 45行 | 327.9ms | 312.1ms | 369.2ms |

同再実行の2枠編集は全再生成302.8ms／枠キャッシュ157.1ms。反復間の変動があるため、小さな差を有意な差とは扱わない。最適化の対象は「この再ラスタ化が必要な時」であり、キャッシュ済み文字をパンするたびにこの時間がかかるという意味ではない。

測定値は [テキストログ](performance-2026-10-07/text.txt) を参照。最初の試行では45行が2048pxで297.9ms、512pxで281.4ms、2枠の片方を変更する試験が全再生成270.1ms／枠キャッシュ136.4msだった。解像度縮小に対して時間差が小さいため、解像度に依存しにくいSVG解析・文字処理の負荷が大きいと推測する。各段階を個別に計測した結果ではない。キャッシュ経路と全描画の画素一致はベンチマーク内で検証している。

## コード上の根拠

### 共通

- `crates/lumapaint-core/src/document.rs:884` の `snapshot()` はレイヤー／オブジェクト一覧、線の輪郭、グラデーション等を生成する。選択レイヤーIDとrevisionだけを必要とする用途にも呼ばれている。
- `src-tauri/src/pixel_paint_macos.rs:631` はプレビュー受信の検証にsnapshot全体を生成する。
- `src-tauri/src/canvas_macos.rs` の `emit_document()` → `checkpoint()`、`src-tauri/src/window_sessions_macos.rs` の `shared_checkpoint()` / `shared_changed()` にsnapshot生成・複製がある。復旧ジョブの置き換えは、送る前のDocument cloneの費用を消さない。
- `Document` は `#[derive(Clone)]` で履歴も所有する。復旧・プレビューに編集履歴まで必要かを分けて、作品の不変スナップショットを設計する価値が高い。

### ベクター

- `crates/lumapaint-core/src/document.rs:6831` の `vector_history_state()` が全SVGレイヤー等をcloneし、`:6898` の `record_vector_edit()` が全オブジェクトを比較する。通常移動は別の差分経路を使うため、この指摘をすべての移動へ広げない。
- 線幅などの一般編集では `vector_svg(...)` を再生成する。Sceneを正本にする際も、読み込みSVGの未対応機能・クリップ・効果の保持が必要。
- `crates/lumapaint-renderer/src/native_bezier.rs` の直接GPU経路は単色塗り等に限定。文字・線・グラデーション・グループ等は対象外だが、それらがすべてCPU描画という意味ではない。対応する保持画像にはSkia/Metal共有経路がある。
- 直接GPU描画の対象拡張より先に、一般編集の差分化と互換経路の可視対象削減を測定する。

### ピクセル

- `crates/lumapaint-renderer/src/paint_cache.rs:39` の `prepare()` は確定ストロークを収集・比較。`:99` から入力中のストローク全体をタイルへ適用し、その後Undoしている。新しい点だけを処理する構造ではない。
- `src-tauri/src/pixel_paint_macos.rs` のワーカーは入力を失わずまとめ、プレビュー転送を変更タイルへ限定済み。これを維持して確定経路を改良する。
- 同ファイルの `worker` 相当の更新ループ（約525行以降）は確定時に全画素をPNG化し、結果にも全画素を複製する。4096×4096 RGBA8なら1コピー64MiB、コード上の2回の `to_vec()` だけで合計128MiBの画素コピーになる。元画像・PNG・履歴・GPU資源は別。
- `crates/lumapaint-renderer/src/layer_effects_gpu.rs:200` 以降でGPU出力をreadbackし、完了を待つ。既存の常駐入力最適化は入力再転送を減らすが、出力読み戻しは残る。過去の効果ベンチマークは [GPU検証記録](layer-effects-gpu-qa-2026-10-06.md) にあり、今回再測定した値ではない。

### テキスト

- `src-tauri/src/text_editor_macos.rs:170` の `render()` は組版キャッシュが当たっても `live_preview()` を呼ぶ。`:1420` でDocumentをcloneして `set_text_object()` を適用する。プレビュー本体を世代単位で保持する改善が可能。
- 同ファイル `measured_layout()`（278行以降）はAppKitレイアウトを確定し、UTF-16列と全文のグリフ／行位置を収集する。日本語・縦中横・欧文回転・合字・フォントフォールバックを壊さず、無変更再描画と変更段落の仕事を分ける必要がある。
- `crates/lumapaint-renderer/src/vector.rs` の `rasterize_svg_region()` はusvg解析を行い、対応時は正規化したSVGをSkia DOMに再構築する。出力だけでなく解析済み構造と組版結果の世代を再利用する。
- `crates/lumapaint-renderer/src/frame_cache.rs:133` の `prepare_layer()` は文字枠画像を再利用しても、出力レイヤー全体のRGBA領域を確保して合成する。2048×2048で16MiB。小Surface化は個々の文字枠には効いているが、最終合成画像の全面確保は別に残る。
- フォントDBはOnceLockで再利用済み。GPUキャッシュにするだけでフォント選択・組版・IMEの仕事はなくならない。最初は解析／組版／描画／readbackを分けて測る。

### アニメーションとメモリ

- `src-tauri/src/timeline_macos.rs` は画像欠落への対策としてコマ変更時に `clear_tiled_preview()` を呼ぶ。同じ露出の再利用や変更タイル更新に置き換える余地はあるが、まず現行表示の正確性を基準画像で固定する。
- 文字枠、保持画像、効果バッファ、Skia contextなどに個別予算がある。これらはアプリ全体のRAM/VRAM上限ではない。ウインドウ数・作業領域・一時画像を含めた総予算とピーク計測が必要。

4. 同じバックエンドで最適化前後の画素一致を確認。異なる描画経路は既存のAA／色差基準を明示し、テキスト位置、透明度、合成順は別に検証する。Undo/Redo、保存往復、失敗時の文書・履歴不変も確認する。
