# 立体メッシュ・可変フォント実軸・漢字筆順 — 2026-10-12

参照：[Motion Reference](https://motion-reference.takayustudio.jp/)。作品のタイムライン再生を優先する。今回の追加は3Dの13項目、可変フォントの9項目、漢字筆順1項目を対象とし、全782デモとの完全な視覚一致を表すものではない。

## 参照の動きと実装

| 対象 | 調査した動き | 現在の実装 |
|---|---|---|
| 立方体 | 8個の共有位置、6面、連続回転と透視 | 面別UVを持つ24頂点・12三角形。裏面除去、XYZ回転、透視、近クリップ、深度、Lambert照明 |
| カバーフロー | 中央を前へ、左右をY軸約60°で回転 | 複数オブジェクトを位置・回転・Zで配置。新規追加時の角度は60° |
| 奥行き・文字の積層 | Z方向の板、8〜16層の文字、傾き | 板のZ配置・カメラ距離、文字の層とタイムライン上の傾き。新規の積層文字は12層の複製・奥行き12px |
| 円筒文字・折り返し | 曲面上の文字、板の回転 | 32分割の円筒UVメッシュ、両面板のX/Y回転 |
| weight wave | 固定位置でwghtを200→900→200、文字ごとの遅延 | Unicode書記素別の実wght。偽の太字や文字のY波で置き換えない |
| 幅・傾斜・複数軸 | wdth・slnt等の補間 | 実フォントのfvar軸と最小・最大値を読み、開始値／終了値を検証して補間 |
| 漢字筆順 | 中心線の順序・方向、長さに応じた時間、画間の間隔、丸い端 | KanjiVGの標準中心線を保存順に描く。長さ×3ms（最低150ms）と設定間隔をクリップ全体の時間に正規化 |

ポインターやスクロールの反応はタイムラインで再生する。サイトのコードやデモのアートワークは同梱しない。

## データと調整

Roboto FlexとNoto Sans JPの未変更TTFをRustプロセス内に読み込む。OSにはインストールしない。同名の静的フォントとの衝突を避けるため、モーションでは `LumaPaint Roboto Flex`／`LumaPaint Noto Sans JP` を使う。一般の文字編集一覧は従来どおりPostScript名を重複させず、専用名を隠す。

自動選択は漢字を含むwghtのみの設定でNoto Sans JP、それ以外はRoboto Flex。Noto Sans JPはwght 100〜900、Roboto Flexはwght 100〜1000、wdth 25〜151、slnt −10〜0などの13軸を持つ。漢字の幅や傾斜は、その字形を描くフォントが対応する軸に限る。混在文字のフォント補完では、実軸が指定された主フォントの描画可能な文字を保持し、欠けた文字のUTF-8クラスタだけを補完する。

筆順データはKanjiVGの6,626字。日本語の標準筆順で、简体中文の筆順体系や全異体字を網羅するデータではない。未収録漢字、異体字セレクター、128字超の対象は変更前に拒否する。筆順の字形はデータの中心線であり、選択フォントの字形や実際の筆圧を再現するものではない。

既存のモーションパネルに奥行き・カメラ距離・XYZ回転・複製数、フォント・軸・開始／終了値、画間の間隔・筆幅を追加。英語・日本語・简体中文に対応し、説明は情報アイコンに置く。設定は文書に保存し、既存のUndo/Redo単位を使う。旧クリップにはデフォルト値を補う。再生用メッシュとGPU画像は保存データに含めない。

## 描画経路と予算

Document・Scene・フォント・画像・GPUリソースはRust側に保持する。WebViewとの通信は命令とカタログ／状態のみ。3D描画はwgpuの透視補間、深度テスト、透明画素の破棄、プレマルチプライド合成、4×MSAAを使う。

原画のテクスチャを再利用し、回転中は三角形の頂点を更新する。テクスチャは最大64項目／64 MiB、1枚は最大2048px／16 MiB、入力SVGは1 MiB。描画対象は64サーフェスまで。MSAA色・深度・合成先の合計は128 MiBまで。GPU生成・転送・保持量は既存の診断経路で計上する。

レイヤー効果、文書クリッピング、輪郭表示、予算超過などは互換SVG経路へ戻る。その経路は投影済み三角形ごとのアフィンUV補間・奥行き順描画であり、ネイティブGPUの透視UV・深度・照明とは同一でない。3D文字の積層は板の重なりで、字形の側面をつなぐ立体押し出しは次段階。

## 検証

macOS／Apple M4／Metalで実施。

- 全782項目をフレーム0・17・29・59で描画し、時間による画像変化を確認。混在文字のwdth/slntが静的フォント補完で消える問題を修正して再実施。
- 実wght・wdth・slntと日本語wghtで画像が変化し、通常の太字・scaleで代替していないことを確認。保存・復元後の画像一致、24px／48pxの英字・合字・結合文字・漢字の混在を検証。
- 全6,626字の全ストロークをパースし、空でない有効な中心線形状を検証。日4画・永5画の順序と方向、途中／完成、未収録字・異体字の拒否と変更前の文書保持を確認。
- Metal実GPUで3つの回転状態、同じテクスチャの再利用、描画順に依存しない前後関係、不透明度0の前面が深度を遮らないことを確認。画像読戻しは検証だけに使用。
- ネイティブアプリで保存済み立方体を読み込み、3Dパラメータ、再生中の形状変化、停止後の原画への復帰を確認。
- 実MotionPanelと検証用transportで、3言語の240px幅、3D奥行き120、Roboto Flexのwdth終了値140と実範囲25〜151、画間150ms・筆幅6の保存を確認。clientWidth＝scrollWidth＝240、空画面・Viteエラー・ブラウザー警告なし。これはUI検証で、ブラウザー側にRustの描画を模擬しない。
- 描画全体274 passed／59 ignored。別途、今回の実GPUテスト1件を明示実行して成功。無関係の手動GPU・性能テストまで今回実施したという意味ではない。
- ネイティブ全体182 passed／1 ignored。実フォントの未対応軸・範囲外値・未収録フォント・無効クリップの扱いを含む。
- コア全体340 passed／1 ignoredに加え、全筆順パスの追加テスト1件成功。

全ターゲットClippy（-D warnings）、整形、空白検査、TypeScript本番ビルドと境界検査に成功。既存のメインJSチャンクの500 kB超警告は残る。モーションパネルは遅延ロードする。ソースと素材のハッシュは [追加検証記録](motion-detail-validation-2026-10-12.json) に記載する。初期の `motion-validation-2026-10-12.json` は初期実装時点の記録として保持する。
