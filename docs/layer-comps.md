# Layer comps — visibility and opacity

🟢 [Done] Named configurations capture the current page's background, layer, and group **own visibility**. Hidden parent groups do not erase a child's own visibility. Applying a comp projects the flags through the existing layer-group renderer path. Newly created/updated comps also capture background and layer **own opacity** before layer/group masks. Groups have no separate opacity control; their mask settings are not captured. Position, lock state, masks, individual vector-object visibility, and artwork remain outside this phase.

🟢 [Done] Create, apply, update, rename, and delete are Rust document edits using the existing layer-group command boundary. Each change is one Undo/Redo transaction; applying an already matching comp is a no-op. Applying does not change the selected layer, selected objects, hierarchy, or artwork. Names are limited to 120 characters; at most 32 comps are stored per page. Names may repeat; identity uses a separate comp ID.

🟢 [Done] Configurations are small ID-to-visibility and ID-to-opacity maps in `LayerGroupsState`, included in native files, page content, recovery snapshots, and existing history. No pixels or document copies are stored inside a comp. Old files without comp metadata load with an empty list. Malformed names, IDs, references, or excessive lists are rejected on loading.

🟢 [Done] Layers added after capture retain their current own visibility. Deleting a layer or group removes its references from every comp in the same history transaction; Undo restores both the content and its references. This also prevents a reused legacy layer ID from inheriting an unrelated comp flag. Reparenting retains the saved own flag and follows the current hierarchy. Updating a comp captures all current layers and groups again.

🟢 [Done] The layer panel contains a collapsible Layer comps block. Clicking a row applies it; the checkmark reports whether its stored visibility and opacity match current settings, so multiple comps may match. The selected row is the target of update, rename, and delete. The name field supports Enter to rename, with IME composition preserved. Descriptions are available through the information icon and action tooltips in English, Japanese, and Simplified Chinese. Unsupported tiled documents and saved-path editing disable editing.
