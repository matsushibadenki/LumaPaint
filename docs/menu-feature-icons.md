# メニューの対象種別アイコン

ユーザー提供のdocs/images内の4画像を元に、src/assets/feature-typesに24×24のSVGを作成した。ペン先と曲線（青）はベクター専用、ピクセル（橙）はピクセル専用、両者を組み合わせた図形（紫）は両対応、重なるフレームと再生／タイムライン（ピンク）はアニメーション用を示す。装飾や現在の選択モードを表すアイコンではない。

WorkspaceMenuの項目にfeature属性を持たせ、コマンドIDで対象を分類する。名称や現在の選択対象で判定しない。文書／共通編集／レイヤー操作は両対応、オブジェクト／書式／ベクター選択はベクター、ピクセル選択範囲／フィルターはピクセル。SVG/PDFの読み込みとリンク画像フレームの配置はベクター、画像の読み込みはピクセル。グループ化はベクター専用、レイヤーグループは両対応。サブメニューは親の分類を継承する。ウインドウ・ワークスペース設定・ショートカット設定・ヘルプなど、対象区分のない項目には付けない。

アイコンは1emで文字サイズに追従し、行の中央に配置する。日本語／英語／简体中文の種別ツールチップを表示する。ウインドウ → タイムラインはアニメーション用の入口で、下部パネルを開く。表示用の要求だけをReactで管理し、作品状態はRustに保持する。

アプリ内メニューはWebViewでSVGを直接表示する。メニューとサブメニューを既存の浮動パネルと同じキャンバス遮蔽経路に登録し、ネイティブキャンバスの手前に表示する。遮蔽矩形を外向きに整数化してCALayerの分数座標による継ぎ目を防ぐ。画像フレームや作品データを転送する経路は追加しない。OSのシステムメニューと他のネイティブコンテキストメニューは既存経路を使う。

チェック／ラジオ状態、コマンド、ショートカット、キーボードによるメニュー操作を維持する。メニュー操作中のキーは作品編集へ伝えない。

CanvasRequestのmenuOpenは、メニューを表示している間だけネイティブPaintViewのヒット判定をWebViewへ渡す表示用フラグ。各PaintViewのRust側に保持し、文書には保存しない。キャンバス上の最初の外側クリックはメニューを閉じるだけになり、選択変更や作画を起こさない。閉じた後は通常のネイティブ入力へ戻る。

## 検証

実Reactメニューで3言語、種別、SVGの読み込み、整列／タイムラインのコマンド呼出しを確認。アイコン12pxと文字サイズ12pxが一致した。macOSの実アプリでネイティブキャンバス上のメニュー、整列サブメニューからの配置変更、Undoと選択3件の維持、タイムラインを開く操作を確認した。型チェック、フロントエンド／macOSアプリビルド、Rust/UI境界、差分の空白チェックを通過。Windows/Linux実機でのキャンバス重なり・入力は未検証。

最終ビルドで分数座標によるキャンバスの継ぎ目が出ないこと、外側クリックでメニューが閉じても3件の選択と保存状態が維持されること、2回目のクリックでは通常の選択操作へ戻ることを確認した。ネイティブ全ターゲットの警告禁止Clippyとfmtも通過。
