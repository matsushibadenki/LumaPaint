# Named layer-effect presets

🟢 [Done] The effects panel contains a collapsible shared library with explicit selection/apply, save current settings, update, rename (including Enter), and delete. A fresh panel initially selects the first stored preset without applying it. Names use separate stable IDs, may repeat, are trimmed and limited to 80 Unicode characters. Up to 64 entries are accepted. The information icon and actions support English, Japanese and Simplified Chinese. Selection alone never applies a preset.

🟢 [Done] Presets capture enabled state, ten adjustment values, four curves and interpolation flags, eight mixer zones, grading zones, blend and balance. A Rust settings schema accepts only these fields and uses the existing core effects validator. The UI also explicitly whitelists these fields when capturing/applying. Masks (including image/selection coverage), screentones, opacity, artwork and document IDs never enter the library. Application merges the preset into the current target and retains its mask/tone settings. Enabled state retains the existing effect-system semantics; changing it may activate/deactivate tone rendering without changing tone parameters.

🟢 [Done] Presets are app preferences, not document content or document Undo state. Applying uses the existing document command and one Undo transaction; reapplying identical effects uses its existing no-op detection. Saving/updating/removing a library item never applies it. The library has its own persisted revision and ID counter. Import/export and cancellable comparison previews remain later work.

🟢 [Done] A Rust app-managed mutex serializes the shared library across editor windows. A mutation validates a copy and writes a same-directory temporary file, flushes it, then atomically replaces `effect-presets-v1.json` in app data. Only successful persistence publishes the new state and ordered notification. Initial reads are capped at 1 MiB; bad versions, unknown fields, IDs/names, array dimensions and invalid effect values are rejected. A bad initial file is preserved and the panel offers retry, without silently replacing it. Getting an absent library does not create a file. Memory is bounded to 64 validated entries and each curve has at most 16 points.

🟢 [Done] The UI subscribes before fetching, ignores older snapshots by revision, unsubscribes on cleanup and ignores response-driven local changes after source unmount. A pending save may finish in the shared library after a layer switch; it never automatically applies effects to the new target. Busy guards prevent duplicate mutations. Load failure disables edits and offers retry; mutation failure preserves prior data. Number-field blur before saving captures the confirmed value.

## Validation

🟢 [Done] Four host Rust tests exercise CRUD, stable IDs, no-op rename, limits, multilingual names, invalid settings and excluded mask/tone fields, native file round trip and state restart, failed persistence with unchanged memory/file, and corrupt/oversized/future files preserved on failure. Workspace all-target Clippy with warnings denied and formatting passed. Frontend typecheck/build, dependency boundaries, notification regressions and diff checks passed.

🟢 [Done] Actual LayerEffectsPanel was exercised in WebKit and Chromium in all three languages at 260px/308px. Tests cover capture/apply without mask/tone transfer, unchanged apply, numeric blur before save, update/rename/delete, busy/error/retry states, stale events and stale initial get, source unmount during save, listener cleanup, locks, 64 entries, long names and fold controls. No framework overlay, console/runtime errors or horizontal overflow occurred. Browser skill was unavailable; an existing Playwright installation used a local-only Vite harness with deterministic transport at `/__effectPresetsQA`. Screenshots confirm the compact select/name/icon layout.

🟢 [Done] The final isolated `LumaPaint Effects QA.app` was exercised in Japanese on macOS/Apple M4/Metal with a 512×256 three-layer fixture. Saving “QA Look” and renaming it to “QA Finish” left the document saved. Changing source contrast from 25 to 35 and updating the preset persisted library revision 3. Document Undo restored source contrast 25 while the preset stayed at 35; Redo restored the document independently. Restarting the app retained the library and its initial first-preset selection. Applying to an untouched blue SVG layer changed enabled state, exposure −1, contrast 35 and the visible Metal canvas. One Undo returned all adjustments to the prior disabled/default state; Redo restored the look. Applying to a hidden layer with pixel mask and tone also saved successfully.

🟢 [Done] Saved native JSON assertions verified all captured settings on source/plain/masked targets, exact mask coverage, transform and link flags, identical f32 mask-density bits, unchanged tone, SVG layers and strokes, and separate preference/document storage. Fixture generation converted f32 values through a generic JSON value; therefore mask density was compared as f32 bits rather than unlike decimal spellings (`0.800000011920929` versus `0.8`). The final debug native build, frontend build/typecheck, formatting and diff checks passed. Final three-language runs in both browser engines also passed after adding default selection and a late-get-error guard. A deterministic load-completion barrier was used before resolving a save during source switching, to distinguish initial selection from response-driven changes.
