# AI image generation

Open the **AI Generation** tab below the document. In **Preferences → AI Generation**, enter an OpenAI or Google Gemini API key and click **Save & Authenticate**. On macOS keys are stored in the native Keychain, never in preferences files or prompt bookmarks. A successful authentication verifies access to the provider's model-list endpoint; image-model permissions, billing and quota are checked by the generation request.

Choose a provider and an accessible image model, then enter a prompt. Default model identifiers are editable. Seventeen optional settings are appended to the prompt: camera, film, lens, lighting, light direction, aperture, shutter speed, ISO, bokeh, visual style, color palette, mood, texture, composition, viewpoint, framing and environment. Categorized dropdowns offer 375 presets with localized labels; each field also supports an unspecified state and a custom value. Preset values use stable English instructions across language changes. Save a named bookmark to reuse or update the complete prompt; bookmarks can be deleted. The bookmark library is shared by editor windows and saved atomically in the application data directory.

Generation sends the prompt to the selected provider. **Edit image** also sends a PNG crop of the selected region of the active image layer. The original image crop is the reference; only pixels inside the exact selection mask are committed, so ellipse, polygon, additive, subtractive and intersected selections preserve pixels outside the mask. Hidden, locked, alpha-locked and vector targets are rejected. Empty selections or regions without image pixels are rejected. Without a selection, or when editing is disabled, the generated image is fitted proportionally inside the canvas and added as a new pixel layer. Both actions produce one Undo/Redo operation.

Image bytes, decoding, resizing and selection compositing remain in Rust. The WebView receives only completion/errors and ordinary document state. Generation is serialized across editor windows. Cancellation prevents applying the result; it does not guarantee that the provider cancels processing or billing. Switching documents or changing the document, target layer or selection during generation prevents stale results from overwriting work. Current limits: 16 megapixel document canvas, 32 MiB API response, 8192 pixel decoded edge and 180 second HTTPS timeout. Existing document image-storage limits still apply. Large tiled documents are not supported by this path. Native image application and secure key persistence currently require macOS, consistent with the existing native canvas host.

API requests use fixed HTTPS provider hosts, reject redirects, validate model names and limit response/image allocations. Error messages do not echo API keys or arbitrary provider error bodies. API use is billed by the provider; application tests use fixtures and never send paid generation requests.

Implemented against the official [OpenAI Images API](https://developers.openai.com/api/docs/guides/image-generation) and [Gemini Generate Content image API](https://ai.google.dev/gemini-api/docs/generate-content/image-generation). OpenAI edits upload an image as multipart form data; Gemini requests contain text and optional inline PNG data and request TEXT/IMAGE responses.

Verification covers provider response parsing, structured prompt validation, exact pixels outside selection, single-step Undo/Redo, new-layer creation, invalid-image and stale-document rejection, and English/Japanese/Simplified Chinese UI flows with mocked IPC. Live provider authentication/generation require a configured user API key and are not exercised by the automated tests.

Local validation on macOS: 710 workspace tests passed (36 hardware/benchmark tests intentionally ignored), Clippy with warnings denied passed, production WebView build passed, and the debug `.app` bundle built successfully. UI fixture checks passed for all three locales. Fixtures use mock IPC and a loopback HTTP server, not real provider keys.


The detailed editor groups controls into look/atmosphere, composition/setting, camera/optics and lighting/exposure. Sections can be expanded independently. Prompt entry and detailed controls use separate columns when space permits, and stack in narrow panels; save and generation actions remain in the bottom bar. The first opening reserves a useful panel height, and subsequent resizing is retained. Existing bookmarks without the eight new fields load with those settings unspecified; custom legacy text is preserved.

Detailed-editor validation: categorized menus, custom values, legacy bookmarks, saved-prompt round trips, generation payloads, loading/error/retry/success, dark/light presentation, and 320/375/414/768/1100 px layouts were checked with Playwright and mocked IPC (Browser plugin not available). The Rust compatibility test covers old bookmark deserialization, new-field persistence/composition and length validation. No external image generation was needed for this UI change.
